第 0 章

预备知识：在编译器之前

Prerequisites: Before the Compiler

这一章不讲编译器。它讲的是编译器这门课默认你"已经知道"、但很少有人真正教过的东西：机器怎样理解程序，字符串和语言的精确含义，树，以及状态机的直觉。如果你觉得自己基础扎实，可以快速浏览；但请至少读一读 0.3、0.4 和 0.6——第 2 章几乎每一页都建立在它们之上。

对话：为什么要先讲"预备知识"？

学生：课件第一页就是"编译器是把一种语言翻译成另一种语言的程序"，我觉得我听得懂啊，为什么还要预备知识？

教授：你当然听得懂这句话。问题是第二章：突然冒出来 Σ、L(r)、(a|c)*b(a|c)*、T: S×Σ→S……很多同学就是在这里掉队的。

学生：确实，那些符号看起来像另一门课。

教授：它们其实只是在精确地说一些非常朴素的事：什么是"一串字符"、什么是"一类字符串"、什么是"一步一步地读"。这一章我们就把这些朴素的事说清楚。学会之后，第二章的符号就只是速记，而不是障碍。

0.1　机器只认识数字

先从最底层说起。一台计算机的内存，可以想成一排编了号的小格子，每个格子装一个 8 位的二进制数（一个字节，byte）。格子的编号叫地址（address）。CPU 做的事情极其单调：从某个地址取出一个数，把它当成"指令"来解释，执行，再取下一个。

这就是机器语言（machine language）：程序是一串数字，每个数字代表一个动作。最早的程序员真的就是这样写程序的——查表、手工编码、用开关或纸带输入。这样写程序费时、乏味、容易出错，而且换一种 CPU，所有数字的含义都变了。

于是人们想：能不能给每个数字起个名字？把 C7 06 叫 MOV，把地址 0000 叫 X，那条指令就成了 MOV X, 2。这就是汇编语言（assembly language）。但是名字和数字之间的对应，总得有人来做——这个"有人"，就是历史上第一批翻译程序：汇编器。

提示：整门课只回答一个问题

"人喜欢用符号和结构来表达想法，机器只认识数字。谁来做中间的翻译？怎么做？"记住这句话，第 1 章的所有内容（编译器、汇编器、解释器、连接器……）都是这个问题在不同层次上的答案。

0.2　程序、语言与"翻译"

在这门课里，我们会同时谈论好几种"语言"，先把它们分清楚：

  • 源语言（source language）：你写程序用的语言，如 C、Pascal，或者课程里的小语言 TINY。
  • 目标语言（target language）：翻译的结果，通常是某台机器的机器语言或汇编语言。
  • 实现语言（implementation / host language）：编译器本身是用什么语言写的。这一点在 1.6 节讨论"自举"时会变得非常有趣。

"翻译"这个词很恰当，但有一个重要的差别：把中文翻成英文，允许一点意译；把 C 翻成机器码，意思必须一字不差。编译器输出的目标程序必须与源程序等价（equivalent）——对任何输入，行为都一样。这条要求贯穿全课：无论做多少"优化"，都不能改变程序的意思。

另一个常见的误解是把"编译"和"运行"混为一谈。编译器只负责翻译；翻译完成后，得到的目标程序才被执行。它们发生在不同的时间，术语上叫编译时（compile time）和运行时（run time）。编译器报告的错误——比如少了个分号、变量没声明——都是编译时错误，程序还一步都没有跑。

0.3　字符、字符串与字母表

编译器读进来的，是一个文本文件：一长串字符（character）。第 2 章的全部内容，就是"怎样把一串字符切成有意义的单元"。所以我们需要一套精确谈论"字符串"的语言。这一节的每个定义都很简单，但请务必读慢一点，因为第 2 章会假设你对它们熟悉到不假思索。

字母表 Σ

一个字母表（alphabet）就是一个有限的字符集合，习惯上记作 Σ（希腊字母 Sigma）。例如 Σ = {a, b, c}，或者 Σ = {0, 1}，或者 Σ = 全部 ASCII 字符。字母表里的成员叫符号（symbol）。

字符串

一个字符串（string）是从 Σ 中取出的符号排成的有限序列。abc、aab、b 都是 {a, b, c} 上的字符串。字符串的长度就是它包含的符号个数。

有一个特殊的字符串，长度为 0，什么符号都没有，叫空串（empty string），记作 ε（希腊字母 epsilon）。它和"空格"不是一回事：空格是一个真实的字符，而 ε 是"没有字符"。很多同学第一次见到 ε 时觉得它多余——但你马上会看到，它是让很多定义变得干净的关键。

连接

把两个字符串首尾相接，叫连接（concatenation）。ab 连接 c 得到 abc。连接不满足交换律（ab ≠ ba），但 ε 是它的"单位元"：任何字符串连接 ε，还是它自己。就像乘法里的 1。

提示：ε 就像乘法里的 1

x · 1 = x，s · ε = s。凡是遇到"某个东西可以出现、也可以不出现"的情形，"不出现"这个选项就用 ε 来表示。第 2 章的 (+|-|ε) 就是这个意思：正号、负号，或者什么都没有。

0.4　语言就是字符串的集合

关键问题：如何精确地说出"哪些字符串是合法的"

"标识符"是什么？"数字常量"长什么样？直觉上你都知道，但计算机需要一个精确的定义。我们需要一种既能描述无穷多个字符串、本身又是有限的说法。

在形式语言理论里，"语言"这个词有一个出乎意料地简单的定义：

一个语言（language）就是一个字符串的集合。

没有别的了。{a, ab, abb} 是一个语言（只有三个字符串）。"所有 C 语言的合法标识符"是一个语言（无穷多个字符串）。"所有语法正确的 C 程序"也是一个语言（每个程序本身就是一个很长的字符串）。所以说，判断一个字符串是不是合法标识符，就是在问："它属不属于这个集合？"

集合可以是无穷的，但我们写在纸上的描述必须是有限的。怎么用有限的规则描述无限的集合？这正是第 2 章的主题——正则表达式是这样的一套记法。为了铺路，先看三种基本的"集合运算"，它们正好对应正则表达式的三种运算。设 A 和 B 是两个语言：

运算记法含义例子（A = {a, ab}，B = {c, ε}）
并A ∪ B属于 A 或 属于 B 的字符串{a, ab, c, ε}
连接A B前半段取自 A、后半段取自 B 的所有拼接{ac, a, abc, ab}
闭包A*把 A 中的字符串任意个（含 0 个）首尾相接{ε, a, ab, aa, aab, aba, abab, …}

请注意闭包的两个要点：第一，"0 个"也算，所以 ε 总是属于 A*；第二，每次可以取不同的成员，aab = a·ab 就是这样得到的。星号 * 叫做 Kleene 星号，第 2 章会大量使用。

补充：Σ* 是"所有可能的字符串"

把闭包用在字母表本身上：Σ* 就是 Σ 上所有有限长度的字符串组成的集合（包括 ε）。因此任何一个 Σ 上的语言，都是 Σ* 的一个子集。"语言 ⊆ Σ*"这个式子你会在教材里经常见到，它只是在说"语言是某些字符串"。

0.5　树：把结构画出来

字符串是一维的，一个符号跟着一个符号。但程序有结构：4 + 2 * 3 里，乘法要先算，所以 2 * 3 是一个整体，然后才和 4 相加。一维的字符串没法直接表达"谁包住谁"，我们需要树（tree）。

几个术语，都很直观：最上面的节点叫根（root）；一个节点下面挂着的叫它的孩子（children），它则是孩子们的父亲（parent）；没有孩子的节点叫叶子（leaf）；从某个节点出发、连同它下面的一切，叫一棵子树（subtree）。

树在编译器里无处不在：第 1 章的分析树、语法树、注释树，都是树。它们在内存里的表示也很朴素——每个节点是一个 C 结构体，里面有若干指向孩子的指针（1.4 节会具体讲）。

树还带来一种思考方式：递归。"计算一棵树的值"可以定义为："如果是叶子，直接返回它的数；否则先计算左右子树的值，再做运算。"这个定义在描述自己的时候用到了自己，但因为树是有限的，它总会在叶子处停下来。编译器里大量的算法都是这个形状。

0.6　状态机的直觉

关键问题：怎样"一步一步"地读一个字符串

扫描程序每次只看一个字符。看了 i，再看 f，它怎么知道这是关键字 if 还是标识符 ifx 的开头？它必须记住到目前为止看到了什么，但又不能什么都记（那样太慢、太占内存）。

想象一台最简单的自动门禁闸机：它只有两种情况——锁着和开着。投币，它从"锁着"变成"开着"；推一下，它从"开着"变回"锁着"。它不记得你投过几次币、几点来的，它只记得当前处于哪种情况。这种"情况"就叫状态（state），投币和推门叫输入（input），从一种情况到另一种情况叫转换（transition）。

这种"只记住当前处于哪个状态、根据输入切换状态"的机器，叫有限状态机（finite-state machine），第 2 章叫它有限自动机（finite automaton）。"有限"是关键：状态的个数是固定的，不随输入变长而增加。这带来两个巨大的好处——速度极快（每读一个字符只做一次查表）、内存极省（只存一个"当前状态"）。这正是扫描程序需要的。

现在把它用在字符串上。假设我们想识别"以字母开头、后面跟任意多个字母或数字"的标识符。我们需要两个状态：状态 1 是"还没读到任何东西"，状态 2 是"已经读到一个合法的开头，后面可以继续"。读到字母时从 1 到 2；在 2 读到字母或数字时留在 2。当输入结束时，如果停在状态 2，就说这个字符串被接受了。第 2 章会把这个想法完全形式化，你会发现所有的形式化都只是把图 0.3 这样的图用集合和函数写下来而已。

提示：手指走图

学自动机最有效的方法就是用手指（或 Apple Pencil）在图上走：从起始状态出发，读一个字符，沿着标着这个字符的箭头走到下一个状态；读完后看看停在哪。请对图 0.3 试一下输入序列"投币、推门、推门、投币"。

0.7　读懂课件代码所需的一点 C

课件里的代码不多，但用到几个 C 语言特性，这里做个速览，保证你在第 1、2 章遇到时不会卡住。

枚举类型 enum

typedef enum { IF, THEN, ELSE, PLUS, MINUS, NUM, ID } TokenType;

枚举就是"给一组整数常量起名字"。IF 其实是 0，THEN 是 1，依此类推。编译器用它来表示"这是哪一类记号"，比用字符串比较快得多，也不容易写错。

结构体 struct

typedef struct {
    TokenType  tokenval;   /* 记号的类别 */
    char *     stringval;  /* 原始的字符串，如 "index" */
    int        numval;     /* 如果是数字，它的数值 */
} TokenRecord;

结构体把几个相关的值打包成一个。char * 是"指向字符的指针"，在 C 里就是字符串。第 2 章的"记号记录"就是这样一个结构体。

循环里的 switch

state = 1;
while (state == 1 || state == 2) {
    switch (state) {
        case 1: /* 根据下一个字符决定去哪里 */ break;
        case 2: /* ... */ break;
    }
}

switch 根据一个整数的值跳到对应的 case；break 跳出 switch。"外层 while、内层 switch(state)"是把状态机写成代码的经典模样，2.4 节会详细分析。

二维数组当作表

int T[NSTATES][NCHARS];      /* T[state][ch] = 下一个状态 */
newstate = T[state][ch];

一张"当前状态 × 输入字符 → 下一状态"的表，就是一个二维数组。整个自动机可以压缩成这张表，代码则退化成"查表、赋值、循环"三句话。

本章小结

  • 机器只认识数字；从机器语言到汇编再到高级语言，每上一层，就需要一个新的翻译程序。
  • 字母表是有限的字符集合；字符串是有限的符号序列；ε 是空串，是连接运算的单位元。
  • 语言 = 字符串的集合。并、连接、闭包三种运算可以从小语言造出大语言。
  • 树表达嵌套结构；递归是处理树的自然方式。
  • 有限状态机：有限个状态、按输入转换、只记住当前状态。它快、省，正是扫描程序所需要的。

  3. 给"电梯门"画一个状态机：状态有"开""关""正在关"；输入有"按开门""按关门""到时"。
