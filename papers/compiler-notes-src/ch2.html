第 2 章

扫描：从字符到记号

Scanning: Regular Expressions and Finite Automata

编译器读到的是一个个字符；它真正想要的是一个个单词——标识符、数、运算符、关键字。把字符流切成单词流，就是扫描。这一章的结构非常清晰，只有两件事：用正则表达式来描述单词长什么样；用有限自动机来识别它们。最后再看怎样把自动机变成几十行 C 代码。

对话：扫描不就是按空格切一下吗？

学生：把字符切成单词，用空格分一下不就行了？

教授：试试 a[index]=4+2。一个空格也没有，但它有八个单词。再试试 x<=y：是 <= 一个单词，还是 < 和 = 两个？ifx 是关键字 if 加上 x，还是一个叫 ifx 的变量？

学生：……好像每种情况都要单独写规则。

教授：如果真的一种情况一条规则，扫描程序会变成一堆无法维护的 if。这一章给你两样工具：一种语言，让你用一行式子精确地说出"什么是一个数"；一种机器，把这行式子自动变成能跑的代码。它们分别叫正则表达式和有限自动机。

学生：正则表达式我用过，在编辑器里搜索文本的那个。

教授：正是同一个东西——它就是从编译器这里发明出来的。学完这章，你会明白编辑器为什么能在几百万行里瞬间搜到结果。

2.1　扫描的任务

扫描（scanning）或词法分析（lexical analysis）阶段，把源程序当作一个字符流读入，把它分割成一个个记号（token）。这是模式匹配（pattern matching）的一个特例，所以我们需要研究模式的描述和识别方法——正则表达式和有限自动机。此外，扫描程序是编译器中唯一逐字符处理整个源文件的部分，它必须尽可能高效。

记号

还是第 1 章的例子：a[index] = 4 + 2 被扫描程序切成 8 个记号（a、[、index、]、=、4、+、2）。记号是扫描程序生成的逻辑单元。课件把程序设计语言的记号分成四类：

类别例子说明
保留字 reserved wordsif、then、while拼写固定，只有一个成员
特殊符号 special symbols+、-、;、:=、<=拼写固定，可能是多个字符
数与标识符 numbers & identifiers3.14、myName、myGrade有无穷多个可能的拼写
字面量 literals"Hello, world!"、'a'字符串和字符常量

记号通常定义为一个枚举类型：

typedef enum { IF, THEN, ELSE, PLUS, MINUS, NUM, ID, ... } TokenType;

记号的属性

一个记号所代表的那串字符，叫它的字符串值（string value）或词素（lexeme）。有的记号只对应一个词素——保留字、特殊符号；有的记号可以代表无穷多个词素——ID、NUM。凡是与记号关联的值都叫属性（attribute）：词素本身、NUM 记号的数值，等等。记号的属性被收集到一个结构化的数据类型——记号记录（token record）里：

typedef struct {
    TokenType  tokenval;    /* 类别：ID、NUM、PLUS…… */
    char *     stringval;   /* 词素，如 "index" */
    int        numval;      /* 若是 NUM，它的数值 */
} TokenRecord;

提示：记号 ≠ 词素

记号是类别（"这是一个标识符"），词素是具体的字符串（"index"）。x 和 index 是同一个记号 ID 的两个不同词素。分析程序只看记号类别，语义分析器才关心词素。

记号函数

扫描程序通过一个函数按需返回输入中的下一个记号，同时计算它的属性：

TokenType getToken( );

关键问题：如何描述记号，又如何高效地识别它们

ID 有无穷多个可能的词素，不可能一一列举。我们需要一种有限的记法来描述无限的集合（这就是正则表达式），再需要一种每读一个字符只做常数工作的机器去识别它（这就是有限自动机）。本章其余部分就是这两件事。

2.2　正则表达式：描述模式

2.2.1　基本定义

正则表达式（regular expression）表示模式（pattern）。与一个正则表达式 r 匹配的字符串集合，叫做 r 生成的语言，记作 L(r)。可用的字符或符号集合叫字母表，记作 Σ。正则表达式包含 Σ 中的符号，但它们指示的是模式，书写时用粗体；此外正则表达式还可能包含元字符（metacharacters）或元符号（metasymbols）——它们不是字母表的成员，而是记法本身的一部分，比如 |、*、括号。

最基本的正则表达式只有三种：

  • 字母表中的单个字符，它匹配自身：r = a，L(a) = {a}。
  • ε 表示空串：L(ε) = {ε}——一个只含空串的集合。
  • Φ 什么都不匹配：L(Φ) = { }——空集。

提示：{ε} 和 { } 不一样

{ε} 有一个成员（空串），{ } 一个成员都没有。前者"接受空输入"，后者"什么都不接受"。这个区别在定义 r* 时很关键：因为 ε 总在 L(r*) 里，所以 L(r*) 永远不是空集。

2.2.2　三种运算

复杂的正则表达式用三种运算从简单的构造出来（按优先级从低到高排列）：

运算元字符写法语言
选择 choice among alternatives|r | sL(r | s) = L(r) ∪ L(s)
连接 concatenation（无）r sL(rs) = L(r) L(s)
重复 / 闭包 repetition, (Kleene) closure*r*L(r*) = L(r)*

请把它和第 0 章的集合运算表对照：三种正则运算一一对应三种集合运算。这就是正则表达式的全部秘密——它只是集合运算的一种紧凑写法。

选择

设 r 和 s 是正则表达式，r | s 匹配任何与 r 或 s 匹配的字符串。例子：a | b 匹配 a 或 b，L(a|b) = {a, b}；a | ε 匹配 a 或空串，L(a|ε) = {a, ε}；L(a|b|c|d) = {a, b, c, d}。

连接

ab 只匹配字符串 ab；(a|b)c 匹配 ac 或 bc。一般地，两个正则表达式 r 和 s 的连接写作 rs，它匹配"前一半与 r 匹配、后一半与 s 匹配"的所有字符串。例如若 L(r) = {aa, b}，L(s) = {a, bb}，则 L(rs) = {aaa, aabb, ba, bbb}。

重复

r* 匹配任意有限多个（含 0 个）与 r 匹配的字符串的连接。a* 匹配 ε, a, aa, aaa, ……。再看一个不那么平凡的例子：

L((a|bb)*) = {a, bb}* = {ε, a, bb, aa, abb, bba, bbbb, aaa, aabb, abba, abbbb, bbabb, bbbba, bbbbbb, …}

每一步可以选 a 也可以选 bb，选任意多次。注意 abb = a·bb，bba = bb·a，而 bab 不在其中——b 单独出现是不允许的。

2.2.3　优先级

重复 > 连接 > 选择。因此 a|cb* 解释为 a | (c (b*))：先算 b*，再和 c 连接，最后和 a 选择。想要别的意思，就像算术一样用括号——括号也是元字符。

补充：为什么不规定结合律？

课件的作业 2.4 问：定义里只规定了优先级，没说 a|b|c 是 (a|b)|c 还是 a|(b|c)，为什么？想想它们的语言：{a,b}∪{c} 和 {a}∪{b,c} 都是 {a,b,c}。集合的并和连接都满足结合律，所以怎么加括号结果都一样，自然不必规定。

2.2.4　五个例题，一次学会写正则

写正则表达式是一种技能，和写程序一样，靠例子学最快。下面五个例题都来自课件，请先自己想，再看解答。

例 2.1　Σ = {a, b, c}，恰好包含一个 b 的所有字符串

思路：这个 b 前面可以有任意多个非 b 的字符，后面也可以。"非 b 的字符"就是 (a|c)，"任意多个"就是加星号。答案：

(a | c)* b (a | c)*

b 不必在字符串正中间：b、abc、abaca、baaaac 都匹配。

例 2.2　Σ = {a, b, c}，至多包含一个 b 的所有字符串

"至多一个"= "恰好一个"或"零个"。用上一题的答案，再加一个"没有 b"的情况：

(a | c)* | (a | c)* b (a | c)*

另一个更紧凑的解法——把 b 变成"可有可无"：

(a | c)* (b | ε) (a | c)*

这里 ε 第一次显示了它的用处：(b|ε) 就是"一个 b 或者什么都没有"。

例 2.3　Σ = {a, b}，一个 b 两边各有相同个数的 a

S = {b, aba, aabaa, aaabaaa, …}。你可能想写 a*ba*——但它也匹配 aab，两边个数不等。事实上这个集合无法用正则表达式描述。原因可以用泵引理（pumping lemma）证明，直觉上是：正则表达式（等价地，有限自动机）没有办法数数——它记不住左边到底出现了多少个 a。这就是 1.1 节说的"单词用 3 型文法、语法用 2 型文法"的分界线。

例 2.4　Σ = {a, b, c}，不含两个连续 b 的所有字符串

这题课件分了几步，展示了"逐步构造"的方法：

  1. 要求每个 b 后面必须紧跟一个 a 或 c：(b(a|c))*。但这漏掉了单独的 a、c，以及末尾的 b。
  2. 允许 a、c 自由出现：((a|c)* | (b(a|c))*)*，化简为 ((a|c) | (ba|bc))*，即 (a|c|ba|bc)*。
  3. 字符串可以以 b 结尾（后面没有字符也不算"连续"）：(a|c|ba|bc)* (b|ε)。

另一个对称的答案是把 b 放在前面看：(b|ε)(a|c|ab|cb)*。两个答案生成同一个语言——正则表达式不唯一。

例 2.5　描述 ((b|c)* a (b|c)* a)* (b|c)* 生成的语言

读法：括号里是"任意多个非 a，一个 a，任意多个非 a，再一个 a"——a 成对出现；整个括号重复任意次，最后再跟任意多个非 a。所以它生成 Σ = {a, b, c} 上含偶数个 a 的所有字符串（0 个也算偶数）。

提示：写正则的三招

① 先写"最典型"的字符串，再问"哪些位置可以变、怎么变"。② "可有可无"用 (x|ε)；"任意多个"用星号。③ 写完后用反例检验：找一个不该匹配的字符串，看看你的式子会不会错误地接受它（例 2.3 的 aab 就是这样发现问题的）。

2.2.5　扩展记法

为了书写方便，实际使用的正则表达式增加了一些扩展。它们没有增加描述能力（每一种都能用三种基本运算写出来），只是更短：

扩展写法等价的基本形式 / 说明
一次或多次重复r+r r*
任意字符.字母表中任意一个字符
字符范围 / 集合[0-9]、[abc]0|1|…|9、a|b|c
不在给定集合中的字符~a、~(a|b|c)、[^a]、[^abc]字母表中除这些之外的任意字符
可选子表达式r?r | ε

课件的例子：natural = [0-9]+，signedNatural = (+|-)? natural。

2.2.6　描述真实的记号

数

nat       = [0-9]+
signedNat = (+|-)? nat
number    = signedNat ("." nat)? (E signedNat)?

请逐层读它：自然数是一串数字；带符号自然数前面可选一个正负号；一个数是"带符号自然数，可选一个小数部分，可选一个指数部分"。于是 42、-3.14、+2E-5、1.5E10 都是 number。注意小数点写成 "."：引号是转义字符，它关闭元字符的特殊含义——不加引号的 . 表示"任意字符"，加了引号才是真正的小数点。

保留字与标识符

reserved   = if | while | do | ...
letter     = [a-zA-Z]
digit      = [0-9]
identifier = letter ( letter | digit )*

标识符：以字母开头，后面跟任意多个字母或数字。x、x1、myGrade 合法；1x 不合法。

注释

注释在扫描时被忽略：扫描程序必须识别它们，然后丢掉。注释可能没有显式的记号——它是一个伪记号（pseudotoken）。两种典型的注释：

{Pascal comment}     {(~})*}
--Ada comment        --(~newline)*

Pascal 注释：左花括号，任意多个不是右花括号的字符，右花括号。Ada 注释：两个减号，然后任意多个非换行字符。

2.2.7　记号定界符

记号定界符（delimiter）是这样一些字符：它们的出现意味着"更长的字符串不可能再是一个记号"。xtemp=ytemp; 中的 = 把两个标识符分开了；空格、制表符和换行都是定界符。要点在于：定界符结束了当前记号的字符串，但它可能是下一个记号的一部分（上例中的 = 本身就是一个记号）。因此定界符不能从输入中删掉——办法有两种：把它退回（backing up）输入；或者在删除之前向前看（looking ahead）一个字符。2.3.3 节的 [other] 记号就是在表达"看到了但不消耗"。

2.2.8　二义性

有些字符串能被几个不同的正则表达式匹配：if 和 while 既符合 reserved 又符合 identifier。语言定义必须给出消除二义性的规则。两条通行的规则：

  • 关键字优先：能解释成保留字的，就解释成保留字。
  • 最长子串原则（principle of longest substring）：能匹配多长就匹配多长。<= 是一个记号而不是 < 和 =；ifx 是标识符而不是 if 加 x。

提示：最长子串原则解释了很多"奇怪"的报错

C 语言里 a+++b 被切成 a ++ + b（最长优先，先吃掉 ++），所以它等于 (a++) + b。而 a+++++b 被切成 a ++ ++ + b，于是报错——虽然 a++ + ++b 是合法的，扫描程序不会"回头"去尝试别的切法。

2.3　有限自动机：识别模式

关键问题：如何把"描述"变成"算法"

正则表达式说清楚了"什么算一个标识符"，但它是一个声明，不是一个过程。我们需要一种能一步步执行、每读一个字符就能决定下一步做什么的东西。

2.3.1　什么是有限自动机

有限自动机（finite automata）或有限状态机（finite-state machine）是描述特定种类算法的一种数学方式。它可以用来识别模式，并且与正则表达式之间有很强的对应关系——第 0 章的闸机就是一台有限自动机。看识别标识符 letter(letter|digit)* 的自动机：

2.3.2　确定性有限自动机（DFA）

把图变成数学，一个 DFA（deterministic finite automaton）M 由五样东西组成：

  1. 一个字母表 Σ；
  2. 一个状态集合 S；
  3. 一个转换函数 T : S × Σ → S（给定"当前状态"和"读到的字符"，告诉你"下一个状态"）；
  4. 一个起始状态 s0 ∈ S；
  5. 一个接受状态集合 A ⊆ S。

M 接受的语言（language accepted），记作 L(M)，是这样的字符串 c1c2…cn 的集合（每个 ci ∈ Σ）：存在状态 s1 = T(s0, c1)，s2 = T(s1, c2)，……，sn = T(sn-1, cn)，并且 sn ∈ A。用人话说：从起始状态出发，按字符逐一转换，最后落在接受状态——正是你刚才用手指做的事。"确定性"（deterministic）的意思是：T 是一个函数，每个（状态, 字符）组合至多对应一个下一状态，永远不需要做选择。

对照图 2.2：Σ = {letter, digit}（把所有字母看成一类），S = {1, 2}，T(1, letter) = 2，T(2, letter) = 2，T(2, digit) = 2，s0 = 1，A = {2}。T(1, digit) 没有定义——这引出下一个话题。

错误转换

严格地说，T 应该对每个（状态, 字符）都有定义。没画出来的转换，按惯例都通向一个错误状态（error state）：一旦进入就出不来、也不接受。

2.3.3　动作：从"接受"到"返回记号"

纯粹的 DFA 只回答"接受还是拒绝"，扫描程序还得做事。课件规定的动作（actions）：

  • 每做一次转换，就把输入中的这个字符移到一个正在累积的字符串里——它将成为记号的词素。
  • 到达接受状态时，返回识别出的记号。
  • 到达错误状态时，生成一个错误记号，或者回溯（backtracking）。

对比图 2.2：那里的自动机在状态 2 "读完就停"，而真实的扫描程序不知道输入什么时候"读完"——它必须读到一个不属于本记号的字符才能确定记号结束了。这就是 2.2.7 节讲的定界符，方括号 [other] 就是"看一眼、不吃掉"。

ε-转换（ε-transition）是一种不看输入、不消耗任何字符就可以发生的转换。它看起来违反直觉——转换可以"自发地"（spontaneously）发生。但它能表达"多选一"，从而让我们不加改动地把多个 DFA 拼在一起：

扩展 DFA 的定义

要容纳 ε-转换和"一个字符多条出路"，需要修改定义中的两处：

  • 字母表要包含 ε：Σ ∪ {ε}。
  • 转换函数 T 的值不再是一个状态，而是一个状态集合——T 允许一个字符通向多个状态。因此 T 的值域是 S 的幂集（power set），即 S 的所有子集组成的集合，记作 𝒫(S)。

NFA 的定义

一个 NFA（nondeterministic finite automaton，非确定性有限自动机）M 由以下部分组成：一个字母表 Σ；一个状态集合 S；一个转换函数 T : S × (Σ ∪ {ε}) → 𝒫(S)；一个起始状态 s0 ∈ S；一个接受状态集合 A ⊆ S。M 接受的语言 L(M) 是这样的字符串 c1c2…cn 的集合（每个 ci ∈ Σ ∪ {ε}）：存在状态 s1 ∈ T(s0, c1)，s2 ∈ T(s1, c2)，……，sn ∈ T(sn-1, cn)，并且 sn ∈ A。

和 DFA 的定义逐字对比，只改了两处：= 变成了 ∈（下一状态是集合中的某一个），字符可以是 ε。课件的三条注记把含义说透了：

  • ci 中的任何一个都可以是 ε；实际被接受的字符串是去掉 ε 之后的那个——所以它的长度可能比 n 小。
  • 状态序列 s1s2…sn 不一定唯一。
  • NFA 不表示一个算法。它可以被一个算法模拟：在每个非确定性的选择处回溯尝试所有可能。

2.4　把自动机变成代码

关键问题：图纸上的 DFA 怎样变成会跑的程序

DFA 是一张图。有三种把它写成程序的方法，从"手工翻译"到"通用引擎"，各有取舍。我们用同一个 DFA 演示三种方法。

方法一：把状态写进程序结构

最直接的写法：用程序的控制结构对应状态——进入 if 分支相当于换了状态，while 循环相当于自环：

{starting in state 1}
if the next character is a letter then
    advance the input;  {now in state 2}
    while the next character is a letter or a digit do
        advance the input;  {stay in state 2}
    end while;
    {go to state 3 without advancing the input}
    accept;
else
    {error or other cases}
endif

短小、易懂，而且很快。缺点是：状态藏在代码的形状里，DFA 稍微复杂一点（比如图 2.6 的 number），嵌套的 if/while 就会变得难以对应和修改。

方法二：状态变量 + 双重 switch

更好的方法：用一个变量保存当前状态，转换用循环里双重嵌套的 switch 实现——外层按状态分支，内层按输入字符分支：

state := 1;  {start}
while state = 1 or state = 2 do
    switch state
    case 1: switch input character
            case letter: advance the input; state := 2; break;
            default:     state := error;
            end switch;
    case 2: switch input character
            case letter:
            case digit:  advance the input; state := 2; break;
            default:     state := 3;
            end switch;
    end switch;
end while;
if state = 3 then accept else error;

现在代码和图一一对应：每个 case state 就是一个圆圈，每个内层 case 就是一条箭头。增加状态或转换只需要增加 case，不必重排整个程序。注意 default: state := 3 分支没有 advance the input——这就是 [other] 的"不消耗"。

方法三：转换表

既然每个内层 case 都只是"给定（状态, 字符）→ 下一状态"，那么整个 DFA 可以压缩成一张转换表（transition table）：行是状态，列是输入字符，格子里是下一个状态。

状态 \ 输入letterdigitother接受？
12no
222[3]no
3yes

空格子表示错误转换；[3] 的方括号仍然表示"转换但不前进输入"。有了表，代码退化成一个与具体 DFA 无关的通用循环：

state := 1;
ch := next input character;
while not Accept[state] and not error(state) do
    newstate := T[state][ch];
    if Advance[state][ch] then ch := next input char;
    state := newstate;
end while;
if Accept[state] then accept;

这里用了两个布尔数组：Advance，按状态和字符索引，指出哪些转换要前进输入（方括号的那些为 false）；Accept，按状态索引，指出哪些是接受状态。课件总结了这种方法的利弊：同样的代码可以用于许多不同的问题——换一个 DFA 只需要换表，代码一行不改；这也意味着表可以由程序自动生成（这就是 Lex/Flex 做的事）。代价是转换表可能需要很大的空间：状态数 × 字符数，对于几百个状态和 256 个字符的真实扫描程序，需要压缩技术。

方法状态在哪里优点缺点
① 程序结构藏在 if/while 的嵌套里最短、最快难对应、难修改
② 状态变量 + switch一个变量，代码逐条对应与图一一对应，易维护仍需手写每个转换
③ 转换表一张二维表代码通用，表可自动生成表可能很大

提示：三种方法其实是同一个东西

方法一把表"编译"进了控制流，方法二把表写成了 switch，方法三把表存成了数据。TINY 的扫描程序用的是方法二（手写），Flex 生成的扫描程序用的是方法三（表 + 通用循环）。理解这一点，你就能看懂任何一个扫描程序的源代码。

小结与作业

本章小结

  • 扫描把字符流切成记号；记号有类别（枚举）和属性（词素、数值）；getToken() 按需返回下一个记号。
  • 正则表达式用三种运算（选择 |、连接、闭包 *，优先级递增）从单字符、ε、Φ 构造模式；L(r) 是它描述的语言；扩展记法 + ? [ ] ~ 只是缩写。
  • 数、标识符、保留字、注释都可以用正则表达式描述；定界符要退回或先行；二义性靠"关键字优先"和"最长子串"消除；有些集合（anban）无法用正则表达式描述。
  • DFA = (Σ, S, T: S×Σ→S, s0, A)；错误转换默认存在；带动作的 DFA 累积词素、在接受状态返回记号，[other] 表示看而不取。
  • 首字符不同的 DFA 直接合并起点；首字符相同要重排。ε-转换让合并机械化，代价是得到 NFA：T 的值是状态集合 𝒫(S)，接受路径不唯一，NFA 本身不是算法。
  • 三种实现：控制结构、状态变量 + 双重 switch、转换表 + 通用循环。
