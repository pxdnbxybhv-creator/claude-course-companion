# IMG_1297 AI 超分到 4K：过程记录

> 这是第一版（纯超分，不改画面内容）。第二版（生成式重绘，AI 补画 4K 细节）见 `NOTES_v2.md`，成品是 `IMG_1297_4K_v2.png`。

## 结论

- 成品：`output/IMG_1297_4K_AI.png`。3840×2160，RGB 8-bit，没有透明通道，带 `sRGB` 块（和原图一样），无损 PNG，6.6 MB（6,646,245 字节），SHA-256 `f893dec93e07f74e3f3de80bc93ebb7ce19906c228e5d606facf79fbb8292b77`。
- 采用的版本：**Real-CUGAN 2x conservative 的结果占 70%，基准图（Lanczos + USM）占 30%，线性混合。**
- 理由：三个模型里，Real-CUGAN 2x conservative 是唯一既能明显变清楚、又不改五官、不出白边、不偏色的；它的缺点是把岩壁的厚涂颗粒和暗部的细纹理抹平了。混入 30% 基准图，能把这部分纹理找回来，又保住大部分清晰度。详细对比见后文。

## 输入

- 仓库里没有 `IMG_1297.png`，用的是对话框上传的原图：2388×1668，8-bit RGB PNG，带 `sRGB` 块（rendering intent 0），SHA-256 `4aebaa15377f9915fce991f45bf7c7cda8a015cffc9522c342168a90921f6aac`。原图没有提交进仓库。
- 按要求用 PIL 裁剪框 `(0, 162, 2388, 1505)` 裁出 2388×1343。我复核了各行的平均亮度：第 161 行 1.1（黑边），第 162 行 122.7（画面开始）；第 1504 行 195.8，1505、1506 两行降到 193.3、188.2（被压暗），1507 行起是黑边；左右两边没有黑边。和给定范围一致。
- 从 2388×1343 放到 3840×2160：水平 ×1.6080，垂直 ×1.6083，两个方向只差 0.02%（整个高度上不到半个像素），所以直接缩放，不裁切、不留边。

## 运行环境

- 云端虚拟机：4 vCPU 的 Intel Xeon（支持 AVX-512 和 AMX），16 GB 内存，**没有 GPU**（系统里没有 `nvidia-smi`），全部用 CPU 推理。
- 虚拟环境 `/tmp/upscale/venv`：Python 3.11，torch 2.14.0+cpu 和 torchvision 0.29.0+cpu（从 download.pytorch.org 的 CPU 源安装，没有 CUDA 依赖），spandrel 0.4.2，Pillow 12.3.0，numpy 2.4.6，scipy 1.17.1。
- 权重、虚拟环境和中间结果都在 `/tmp/upscale`，没有提交进仓库。

## 处理流程

1. **基准图**：PIL `crop` → `resize((3840, 2160), LANCZOS)` → `UnsharpMask(radius=1.4, percent=70, threshold=3)`。
2. **AI 推理**（`scripts/run_model.py`）：
   - 用 spandrel 加载模型。`.safetensors` 直接读取；只有 `.pth` 的 Real-CUGAN 用 `torch.load(..., weights_only=True)` 读取。部分 `.safetensors` 存的是 fp16 权重，统一转成 fp32。
   - 推理精度用 fp32、4 线程。我也测了 bf16（AMX 加速），只快 1.5–2.5 倍，而且和 fp32 的结果平均差 0.4–0.6 个色阶，单像素最大差 1.6–39 个色阶，不值得换。
   - 分块：先把整张图四周各反射填充 16 px，这样模型在真实图像边缘看不到人为的黑边。然后均匀切成 6×4 = 24 块，每块 444×380 px，相邻块至少重叠 48 px（在 2x 输出上是 96 px）。重叠区按线性羽化权重做加权平均：每块最外沿权重接近 0，而分块边缘正是受零填充影响最大的地方。内存很宽裕：跑最重的 UltraSharp 时抽查，系统已用内存约 1.8 GB。
   - 模型输出先截断到 [0, 1]，再用 32-bit 浮点的 Lanczos（PIL 的 `F` 模式，逐通道处理）缩放到 3840×2160，最后只做一次四舍五入到 8-bit，避免多次取整在暗部造成色带。
3. **混合**（`scripts/make_blends.py`）：在浮点下计算 `s × AI + (1 − s) × 基准图`，s 取 0.8、0.7、0.6，最后一次取整。
4. **保存**（`scripts/make_final.py`）：写 RGB PNG，加 `sRGB` 块（intent 0），用 `optimize=True` 做无损压缩。保存后重新读回校验：尺寸 3840×2160，colortype 2（RGB，没有 alpha），文件里只有 `IHDR`、`sRGB`、`IDAT`、`IEND` 四种块，像素逐一相同。

说明：

- 实际耗时比小块估算慢 1.2–1.5 倍。一是整块 444×380 的缓存效率比 256×256 低，二是 AnimeSharpV4 和 UltraSharp 运行期间我用 `nice` 低优先级跑了少量分析脚本。缩放到 4K 只需 0.7–2 秒。
- **下载问题**：`JacksonYan/Real-CUGAN` 模型仓库的文件返回 403。原因是这个老仓库的 LFS 文件会跳转到 `cdn-lfs.hf.co`，而这个域名被本环境的出网策略拦截。存储在 Xet CDN（`us.aws.cdn.hf.co`）上的仓库可以正常下载，所以我改用 Space `mayhug/Real-CUGAN` 里的同一份权重，并用 sha256 在三个独立副本之间做了核对。全程没有从 GitHub Release 下载任何东西。

## 客观指标

所有版本都是量化成 8-bit 以后再测的。“一致性 PSNR”指把 4K 结果用浮点 Lanczos 缩回 2388×1343 以后和原图比：数值越低，说明画面内容被改得越多。“细节”指亮度高频分量（图像减去它自己 σ=1.5 的高斯模糊）的标准差，以纯 Lanczos 放大为 1。“纹理相关”指带通分量（σ 0.8 减 σ 3）和纯 Lanczos 的相关系数，越低说明原有纹理被重画或抹掉得越多。“过冲”指某个通道超出纯 Lanczos 7×7 邻域最大/最小值 6 个色阶以上的像素比例，白边、振铃和把线条加深都会计入。“暗部平坦占比”指区域 4 里 5×5 邻域完全同色的像素比例，这个值偏高、同时纹理又少，是出现色带的前兆。

## 按要求逐项检查

- **纹理和塑料感**：纯 Real-CUGAN 把岩壁块面内部的颜料颗粒和细排线抹掉了，只留下锐利的笔触边缘，是典型的“动漫模型塑料感”（岩壁纹理相关 0.93，暗部 0.52）。AnimeSharpV4 几乎完整保留了原图纹理，也包括原图的压缩噪点。UltraSharp 纹理最多，但有一部分是它自己生成的：暗部提亮后能看到规则的鱼鳞状纹路。70% 混合把岩壁纹理相关拉回到 0.96、暗部拉回到 0.76，200% 放大看岩壁的颗粒感明显回来了。
- **五官**：Real-CUGAN conservative 和它的几个混合版本都没有改变五官的位置、大小和形状，只是给下颌和发丝加了一圈较深的动画风轮廓线（这是“过冲”数值偏高的主要来源）。**UltraSharp 在银发人物眼睛周围、脸颊边缘和下巴附近生成了深色碎点**，这张只有约 40 px 宽的小脸被它改变了，这是放弃它的主要原因。no-denoise 把原图噪点锐化成小块，改动也比 conservative 大。AnimeSharpV4 基本没有改动。
- **白边和振铃**：领带、衬衫、马甲、剑身这些高对比边缘在 200% 下看，Real-CUGAN 和各混合版本都没有白边或振铃。**UltraSharp 沿银发发束出现了细白线**（见 `extra-edge-halo-check-…`）。基准图本身带一点 USM 光晕，混合进 30% 后在 200% 下也看不出来。
- **色偏**：成品的平均色偏是 R −0.02、G −0.06、B +0.17 个色阶，局部最多 1.4 个色阶，肉眼看不出来。UltraSharp 整体偏亮、偏蓝约 1 个色阶，局部最多 5.6；no-denoise 偏品红约 0.9，局部最多 5.3。
- **暗部色带**：所有版本在亮度拉高 5 倍后都没有看到阶梯状的色带。原图暗部本身带块状噪点（看起来像 JPEG 压缩块），Real-CUGAN 把它们平滑掉了，70% 混合会带回一点，只有提亮后才看得出。
- **接缝**：数值和图像都没有发现，见上文。边缘也检查过：成品四边相对往里第 8 行/列的亮度差在 −0.7 到 −0.8 之间，比原图裁剪后本身的 −1.1 到 −2.0（画面自带轻微暗角）还小，没有黑边或压暗的边。

## 为什么选 70%

- 纯 Real-CUGAN 最清楚，但岩壁和暗部偏平。60% 找回的纹理最多，但原图的锯齿、块状噪点和 USM 光晕也回来得比较多，脸和发丝开始发毛。80% 和纯 CUGAN 的观感接近，岩壁仍然偏平。
- 70% 在 200% 放大下的观感最平衡：发丝和五官的线条基本保持 CUGAN 的干净（人脸区域的细节能量是 1.80，纯 CUGAN 为 2.06–2.09，基准图约 1.35）；岩壁的颜料颗粒找回了大半；色偏最大也只有 1.4 个色阶。它也正好在你给的 60%–80% 区间中间。
- AnimeSharpV4 虽然最忠实，但它在人脸区域的“细节”指标和加了 USM 的基准图差不多（1.30–1.34 对 1.34–1.36），不符合“尽量补出细节”的目标。UltraSharp 细节最多，但改了小脸、出白边、有偏色，这三点都是这次明确要避免的。

## 不足

- AI 能补的只有“更清楚的边缘和线条”，补不出原作真正的细节。原图只有 2388 px 宽，本身又是 iPad 截图（从暗部的块状噪点看，截图前很可能经过了缩放和 JPEG 压缩）。放大到 4K 后，那张四十来像素宽的小脸只是轮廓更清楚，眼睛里的细节不会凭空变多。如果能找到原始大图，直接用原图会比任何超分都好。
- Real-CUGAN 的动画化倾向没有完全消除：下颌、发丝外侧还是能看到一圈比原作略深的轮廓线；衣服上的金色花纹比原作简化了一些。
- 岩壁的纹理仍然比原图略平（纹理相关 0.96），暗部的细颗粒也比原图少（细节能量是原图直接放大的 0.65 倍）；混入的 30% 基准图带回了少量原图锯齿和压缩块，要放大到 200% 或拉亮才看得出。
- 成品整体偏蓝 +0.17 个色阶，局部最多 1.4 个色阶，属于测量层面的差异，肉眼看不出。
- 纵横比从 1.7781 缩放到 1.7778（16:9），垂直方向比水平方向多拉伸 0.02%，肉眼不可见。
- 分块推理对 Real-CUGAN 来说不完全等于整图一次推理（原因是上文的 SE 模块），不过差异已经被羽化消化，看不出来。

## 复现

脚本在 `output/scripts/`，路径写死在 `/tmp/upscale` 下（模型放在 `/tmp/upscale/models`，原图放在 `/tmp/upscale/work/IMG_1297.png`）：

```bash
python make_baseline.py                           # 基准图
./run_all.sh realcugan2x_conservative animesharpv4_2x_rcan ultrasharp_4x   # 各模型推理 + 缩放到 4K
```
